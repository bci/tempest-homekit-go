## Summary

The service builds, vets and passes its full test suite on main, but the review found
several real defects. The ones fixed here are surgical and each has a test that fails
before the fix:

- two crash paths (a nil HTTP response in the history loader, and any `null` field in a
  UDP broadcast, which killed the listener goroutine and so the whole process);
- a data race between the web alarm-status endpoint and alarm evaluation;
- a data-loss bug in the alarm editor's "save to .env", which could duplicate the whole
  `.env` (credentials included) or silently delete unrelated settings;
- configured syslog priority being ignored;
- `--disable-internet` still calling an internet elevation API;
- two small panics on short secrets, an API token printed in debug output, and nine tests
  that would nil-dereference instead of failing.

The biggest open items need Kent: **the Windows build is broken** (`log/syslog` is imported
unconditionally), the alarm editor and dashboard listen on all interfaces with no
authentication while the editor can rewrite `.env`, the static assets are served relative
to the working directory, `package.json` is gitignored although the hook and tests need
it, and a cluster of unit inconsistencies (rain daily vs accumulated, wind mph vs m/s) in
the alarm evaluator and dashboard.

Counts: **10 fixes**, **~70 findings not fixed** (grouped below), **14 questions**.

## Fixed

Line numbers are on this branch.

1. **`pkg/weather/client.go:767` — history loader panicked on network errors.**
   *What:* in `GetAllHistoricalObservations`, when every retry for a day failed at the
   transport level, `resp` was nil and `io.ReadAll(resp.Body)` panicked; after exhausted
   429 retries or a non-200 it read an already-closed body and counted the day as empty a
   second time (so it stopped after 2 bad days, not the intended 3).
   *Fix:* after the retry loop, skip to the next day when there is no 200 response.
   *Why:* `--history-read` against a flaky network crashed startup.
   *Verified:* `TestGetAllHistoricalObservations_NetworkErrorsDoNotPanic` (panicked before)
   and `TestGetAllHistoricalObservations_Non200CountsOnce` (got 2 requests before, 3 after)
   in `pkg/weather/history_retry_test.go`.
   *Behaviour note:* a run of HTTP errors now tries 3 days before giving up instead of 2,
   which is what the existing `consecutiveEmpty >= 3` checks say was intended.

2. **`pkg/udp/listener.go:439` — one malformed UDP packet crashed the process.**
   *What:* the decoders use unchecked `.(float64)` assertions and `Evt[0]` indexes; a JSON
   `null` (or an empty `evt`) panicked the listener goroutine, which is not recovered, so the
   whole service exited.
   *Fix:* `processMessage` recovers, logs `Dropping malformed UDP message` at warn, and drops
   that packet. Valid packets are processed exactly as before.
   *Verified:* `TestProcessMessage_MalformedPacketsDoNotPanic` (5 sub-cases, all panicked
   before) in `pkg/udp/malformed_message_test.go`.

3. **`pkg/alarm/manager.go:495` — data race between `/api/alarm-status` and alarm evaluation.**
   *What:* `GetConfig` claimed to return a copy but shared the `Alarms` slice; the web
   handler iterated it (reading `TriggeredCount`, last-fired time) without the lock while
   `ProcessObservation` wrote them under the lock.
   *Fix:* copy the `Alarms` slice under the read lock. Signature unchanged; doc comment now
   says exactly what is and is not copied.
   *Verified:* `TestManager_GetConfig_AlarmsAreCopied` (failed before) and
   `TestManager_GetConfig_ConcurrentWithProcessObservation` (3 `DATA RACE` reports under
   `-race` before, clean after) in `pkg/alarm/manager_getconfig_copy_test.go`.

4. **`pkg/alarm/editor/server.go:989` and `:1125` — "save to .env" could corrupt `.env`.**
   *What:* the contacts and tags "save to env" paths look for `CONTACT_LIST=` / `TAG_LIST=`
   and then scan forward for a line containing `'` to find the end of the value.
   (a) If none was found, `endLine` stayed -1 and `lines[endLine+1:]` re-appended the whole
   file, duplicating every setting (credentials included). (b) If the value was unquoted
   (`CONTACT_LIST=[]`), the scan swallowed every following line up to the next unrelated
   quoted variable and deleted them.
   *Fix:* only an opening quote that is not closed on the same line starts a multi-line
   value; an unterminated value replaces just the key's line.
   *Verified:* `TestSaveToEnv_UnterminatedValueDoesNotDuplicateFile` (contacts and tags;
   file duplicated before) and `TestSaveContactsToEnv_BlockDetection` (unquoted case lost
   `SMS_TEMPLATE='hello'` before; the single-line and multi-line quoted cases pass before
   and after) in `pkg/alarm/editor/env_save_test.go`.

5. **`pkg/alarm/notifiers.go:145` — syslog `priority` setting was ignored.**
   *What:* the priority (error/warning/info) was computed and passed to `syslog.Dial`/`New`,
   but the message was always written with `writer.Warning`, which forces warning severity.
   *Fix:* `writer.Write`, which uses the configured priority. Default stays warning.
   *Verified:* `TestSyslogNotifier_UsesConfiguredPriority` sends to a local UDP listener and
   checks the `<PRI>` header: error arrived as `<4>` before, `<3>` after; info `<4>` → `<6>`.

6. **`pkg/config/config.go:378` (+ `:711`) — `--disable-internet` still called the internet.**
   *What:* without `--elevation`, `LoadConfig` auto-looks-up elevation; for station names in
   the built-in city table that calls `api.open-elevation.com`, even in offline mode.
   *Fix:* skip the lookup when `DisableInternet` is set (fallback elevation is used, as it
   already is when the lookup fails). The lookup is reached through a package variable
   `stationElevationLookup` so a test can observe it — the same injection style the repo
   already uses (`DataSourceFactory`).
   *Verified:* `TestLoadConfig_DisableInternetSkipsElevationLookup` (offline: no lookup;
   online: lookup still happens).

7. **`pkg/alarm/notifiers.go:625` — panic on a Twilio account SID shorter than 10 chars.**
   *What:* the debug log line sliced `accountSID[:10]` unconditionally (arguments are
   evaluated even when debug is off).
   *Fix:* slice only when longer than 10.
   *Verified:* `TestSendTwilio_ShortAccountSIDDoesNotPanic` (no recipients, so no HTTP).

8. **`pkg/alarm/smstest.go:211` — `maskString` panicked on a 1-character secret** and
   printed a 2-character secret in full. Now returns `***` for 1–2 characters.
   *Verified:* `TestMaskString_ShortInputs`.

9. **`pkg/weather/client.go:696` — API token printed in debug output.** The `--history-read`
   debug line printed the full request URL including `token=`. It now prints the URL
   without the query string. *Verified:* by reading; output-only change.

10. **Test robustness and readability.**
    - `pkg/alarm/notifiers_coverage_test.go` (4), `notifiers_file_test.go` (2),
      `notifiers_sms_test.go` (3): `if err == nil { t.Error(...) }` followed by `err.Error()`
      would nil-dereference and panic the test binary instead of reporting a failure;
      changed to `t.Fatal`. *Verified:* tests pass.
    - `pkg/homekit/modern_setup.go:369`: the `GetAvailableSensors` doc comment sat on the
      closing brace of the previous function (`} // GetAvailableSensors ...`), so `go doc`
      did not attach it; moved onto its own line.

### Security

- **Alarm editor (`--alarms-edit`) and dashboard listen on `:port` (all interfaces) with no
  authentication.** The editor can rewrite the alarm file and `.env` (contacts, tags), and
  falls back to writing the *tracked* `.env.example` when `.env` is missing (Q6, Q7).
- Alarm editor `script.js` (`renderAlarms`, tag/contact editors, `result.expanded`) puts alarm
  names, conditions, tags and contacts into `innerHTML`/inline `onclick` unescaped — stored
  XSS reachable by anyone who can reach the unauthenticated editor; a `'` in a name also
  breaks the buttons. Dashboard `script.js` interpolates `status.stationURL` into
  `innerHTML`. Fixing means rewriting render code — not surgical (Q6).
- `pkg/alarm/notifiers.go` `EmailNotifier.Send`: the expanded subject goes into the SMTP
  header unencoded, so CR/LF from template values could inject headers. Template values come
  from the operator's own config and sensor numbers, so exposure is low; noted.
- `pkg/weather/datasource_api.go`, `pkg/service/datasource_factory.go:77`: a custom station
  URL (which may embed a token) is logged at debug/info.
- `service.go:173` logs the HomeKit PIN at info level; `install-service.sh` ships the
  well-known default PIN `00102003`.
- `scripts/start-godoc.sh:57` installs unpinned `godoc@latest` without asking.

### Correctness — alarms

- `evaluator.go` (`rain_daily`) reads `obs.RainAccumulated`, while the manager stores the
  previous `rain_daily` from `RainDailyTotal` and `{{sensor_info}}` uses the daily total, so
  `*rain_daily`/`>rain_daily` compare different quantities; `rain_rate` also reads
  `RainAccumulated` (Q8).
- `evaluator.go`: a condition mixing `&&` and `||` splits on `&&` only — no precedence or
  grouping; `EvaluateWithAlarm` dereferences `obs` before any nil check.
- `schedule.go` `calculateSunTimes` builds UTC hours into `time.Date(..., date.Location())`
  without conversion — sun schedules are off by the UTC offset outside UTC; `isActiveSun`
  cannot match an overnight (sunset→sunrise) range (Q9).
- `manager.go` `reloadConfig`: every file save resets cooldowns, change-detection baselines
  and `TriggeredCount` (can re-notify immediately); no debounce, so one save can reload
  several times (Q10).
- `manager.go` `ProcessObservation` holds the write lock while sending notifications
  (SMTP/Graph/Twilio/webhook with 10 s timeouts), blocking the status getters.
- `manager.go` `Stop` is not idempotent (second call panics on closed channel); same pattern
  in `weather/datasource_api.go` and `udp/listener.go` (`stopChan` never recreated).
- `notifiers.go` `sendAWSSNS`: with a topic ARN it publishes once per `To` entry (duplicates);
  `sendTwilio` defers `resp.Body.Close()` inside the loop.
- `notifiers.go` CSV notifier picks the 11-column header whenever the first message contains
  a comma; the deferred `writer.Flush` error is ignored. JSON file rewrite is not atomic.
- `notifiers.go` `formatNumber` (and `main.go`'s) mis-format some negatives (`-,123`).
- `EventLogNotifier` on Windows only calls `logger.Info`; `eventlogtest.go` tells users to
  look in Event Viewer.
- `emailtest.go` chooses Microsoft 365 only when all three MS365 vars are set, but
  `LoadConfigFromEnv` chooses it when `MS365_CLIENT_ID` alone is set.
- `types.go` `Channel.Validate` error text omits `csv`/`json`; `Validate` mutates (fills
  defaults).
- Alarm editor `server.go`: no mutex around `s.config`/`s.contacts` (concurrent handlers
  race); `handleSaveContacts` replaces `s.contacts` before rejecting an invalid `saveType`;
  `handleValidateJSON` does not expand `{{app_info}}` although the UI offers it. Writes are
  `os.WriteFile` (non-atomic). The mutex is a reasonable next fix but touches every handler.
- Alarm editor `script.js`: `editAlarm` never clears the schedule form (previous alarm's
  weekdays/lat-lon carry over); tags/contacts arrays alias the alarm (cancel does not undo);
  new editor rows all get `data-index="-1"`; blank cooldown sends `NaN`→`null`; `saveAll`
  says "saved" but only downloads a file; the emoji picker always targets `consoleMessage`.
